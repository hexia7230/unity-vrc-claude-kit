# 触れて反応する NPC と過ごすワールドを作る

実例は `knowledge/case-studies/milfy-home.md` (「ミルフィと同棲できる部屋」、2026-11 に 1 日で制作)。何を頼まれ、どの順で何を決めたかが書いてあるので、先に読む。

## うまくいった進め方 (守ること)

1. **先に調べる。手元の SDK の中身で確かめる。**
   - 次の機能が本当に使えるかを、設計の前に、入っている SDK のソースで確認する。ドキュメントだけで判断しない。
     - ワールドの PhysBones / Contacts / Constraints (3.10 以降、Udon のイベントあり)
     - UdonBehaviour の `OnAnimatorIK`
     - NavMeshAgent
     - Rigidbody と Joint のラグドール
     - 引数付きのネットワークイベント `[NetworkCallable]`
2. **案を出し、決めるのはユーザー。**
   - 「どんな要素を足す？」のような質問には、効果と手間を 1 行ずつ添えた番号付きの案で答え、番号で選んでもらう。
   - 頼まれない限り、仕組みは簡単なままにする。
3. **当て推量で直して遅いテストを回し直さない。**
   - 姿勢・握り・見た目は、目標を数値の条件にする (接点・距離・角度・色の統計)。
   - 速いループで解く (エディタの描画か node の模擬。再生モードは使わない)。
   - 参考と見比べる独立の審査役 (サブエージェント) の合格を条件にする。審査役より先に「合格」と言わない。
4. **Unity の外で確かめられる物は外で確かめる。** 例: 脳は C# の値をそのまま読む node の模擬で、場面を数秒で回す。
5. **ClientSim の次は実機。**
   - 再生モードの場面テスト (`Play*`) を書く。中身は、触る・掴む・小物・計算役の引き継ぎ。数値と写真を残す。
   - ユーザーがゲーム内で確かめ始めたら、ClientSim での確認はやめる。ユーザーの指摘をまとめて受けて、まとめて直す。
6. **キャラクターの品質方針。**
   - しないこと: メッシュの間引き、顔・髪・目・肌のテクスチャ解像度の低下、表情の簡略化。
   - 削るのは見えない物だけ: 使わないブレンドシェイプ (実例では 820 → 117)、着ていない服、隠れて見えない部品、小物。
7. **権利と運用。**
   - アップロードはユーザーがする。
   - 購入したアバターのモデルを含むワールドは、規約を確認するまで Friends+ 以下で運用する。
   - 素材のクレジット (CC BY の効果音など) は、ワールド内の板に載せる。
8. **重い処理 (Unity / Blender) は同時に 1 つだけ。**
   - 撮影は ARGB32 + sRGB で行う。ARGBHalf + ReadPixels は線形の値のままになり、実際の画面より暗く写る。

## 作る順番 (確認表)

1. **部屋**
   - .blend を FBX と材質の値のファイルに書き出す。
   - Blender の手続きの模様は、物ごとに画像へ焼く。
   - 材質は Unity で作り直す。
   - 外箱の面が外向きなら、内向きの面を足す。
   - 壁と床の当たり判定は箱にする。
   - スポーンは、光線で歩ける床を確かめて置く。
2. **見た目**
   - 光は焼き込み: 太陽、窓の面光源、細かいライトマップ、はね返り 4 回。
   - ライトプローブは 0.45 m 前後の間隔で置く。家具の箱の中には置かない。
   - 反射プローブを置く。
   - ポスプロは軽くし、レイヤーは 22 にする。AO は使わない (前髪の下にサングラス状の影が出る)。
   - アバターだけを照らす光を置き、キャラクターを部屋になじませる。
3. **キャラクター**
   - Humanoid と lilToon で取り込む。
   - 見えない物を削る。
   - Pickup レイヤーに置いて、アバター用の光とプローブを受けるようにする。
4. **アニメーター**
   - 層は 4 つ: 体の状態、顔の状態、手の状態、まばたきと呼吸の加算。
   - 歩き・待機・仕草は、筋肉の値のカーブから作る。GoGoLoco やプロキシのクリップは 1 コマの静止ポーズなので、そのままでは動かない。
   - アバターの AFK モーションは使わない (変な姿勢で固まる)。
5. **脳**
   - 約 30 細胞の発火率の神経網。計算役が 0.25〜0.5 秒ごとに回す。
   - 行動は点数で選ぶ。人ごとの好き嫌いを覚える。
   - 人格は結合の値で決める (`references/brain.md`)。
6. **手足と表情の層**
   - 同期した「動きのもと」から、各端末が振動子と周期の合わない揺らぎを作る。
   - それで頭・背骨・肩の角度と表情の重みを、アニメーションの上に足す。
   - 手の仕草は、実際の骨から測った目標へ IK で手首を運ぶ。
7. **体**
   - 当たり反応: 臨界減衰のばねと、半歩のよろけ。
   - ラグドールは強い当たりのときだけ (手が速い、走ってぶつかる)。
   - 掴みは、骨に付けた見えない PhysBone にする。表示・縁取り・振動が出ないので没入感を壊さない。
   - 掴まれた所を支点に、手の方へ引き寄せる。ぐにゃっとさせない。
   - 揺れ物 (胸・お尻・上着の裾) は掴めないようにする。
8. **触れる所**
   - T ポーズでメッシュの表面に合わせて、約 27 か所の接触の受け手を骨の子に置く。
   - 指か手のひらかは `matchingTags` で見分ける。
   - 体に近い所は、親しさ (好感度 × 打ち解け) で許す範囲を広げる。
9. **ふれあい**
   - 見つめると照れる、手をつなぐと付いてくる、撫でると頭が付いてくる、首をかしげるとまねる、隣に座る、仲良しのそばでうたた寝する。
   - 小物は簡単な決まりで: 2 口で食べる、飲む、暇なら遊ぶ、取り上げると追いかける。
10. **同期**
    - 計算役 (オーナー) はインスタンスのマスターにし、外れたら取り戻す。
    - 状態は小さなまとまりを手動で同期する。
    - 触る・掴むは、触った本人の端末が判定し、`[NetworkCallable]` で全員に送る。
    - シーンを作ったら、各 UdonBehaviour の同期の種類を宣言どおりにそろえる。
11. **ギミック**
    - テレビ (YamaPlayer) とアンビライト
    - 壁の掲示: 気持ちと好感度の上位 3 人
    - 「脳の中」の表示
    - QvPen、入室ログ、クレジット
12. **確認**
    - 構成の確認 (CheckBatch) が ALL PASS になること。
    - 再生モードの場面テストを回す。
    - 容量を測る (実例は約 40 MB)。
    - アップロードはユーザーがする。blueprintId をテキストに残し、作り直しても同じワールドになるようにする。
